    4. La vista y su modelo

    Hasta ahora, las acciones generaban ellas mismas sus respuestas: texto, JSON y algunas etiquetas HTML escritas como una cadena de caracteres. En una aplicación MVC, este es el papel de una vista: un archivo que describe el HTML de la página, con marcadores de posición para los datos que le transmite la acción, el modelo de la vista.

    [Laravel] incluye su propio motor de vistas, [Blade]. Una vista [Blade] es un archivo cuyo nombre termina en [.blade.php], almacenado en la carpeta [resources/views] de la aplicación. Es un archivo de texto, en este caso HTML, en el que se interpretan tres tipos de etiquetas en el servidor:

    • [{{ expression }}]: el valor de una expresión [PHP] insertado en la página;
    • [@instruction]: una directiva: condición ([@if]), bucle ([@foreach]), herencia de plantillas ([@extends], [@section]), inclusión ([@include])... Una directiva comienza con [@], seguido de su nombre;
    • [{{-- commentaire --}}]: un comentario, que no aparece en la página generada.

    Todo lo demás se copia tal cual. Las expresiones se escriben en [PHP]: no hay un segundo lenguaje que aprender. [Blade] se parece así a [Razor], el motor de vistas de [ASP.NET Core MVC], que también mezcla HTML y código, y que también utiliza el carácter [@]; se diferencia de [Thymeleaf] ([Spring MVC]), cuyas vistas son archivos HTML válidos enriquecidos con atributos [th:]. Una vista [Blade] no se ejecuta tal cual: en su primer uso, [Blade] la compila en un archivo [PHP] estándar, almacenado en [storage/framework/views], que luego reutiliza mientras la vista no cambie. Veremos cómo es este archivo.

    <?php
// app/Http/Controllers/ViewsController.php: acciones que devuelven una VISTA

namespace App\Http\Controllers;

use App\Models\PageModel;
use Illuminate\Http\Response;
use Illuminate\View\View;

class ViewsController
{
    // view: el motor Blade construye la página a partir de la vista
    // resources/views/views/index.blade.php y de las variables pasadas en el
    // arreglo (aquí una sola, [model]); la página producida es la respuesta de la acción
    public function index(): View
    {
        $model = new PageModel(
            'My first view',
            'This page was built by Blade, on the server.',
            date('H:i:s'));
        return view('views.index', ['model' => $model]);
    }

    // la misma vista con otro modelo; o otra vista, con el código 404
    public function hello(string $name): View|Response
    {
        if ($name === 'unknown') {
            // la página, enviada con el código 404
            return response()->view('views.unknown', ['name' => $name], 404);
        }
        $model = new PageModel(
            "Hello $name",
            'This time, the title of the page comes from the URL.',
            date('H:i:s'));
        return view('views.index', ['model' => $model]);
    }
}
    • Líneas 17–20: la acción construye el modelo de la vista. La función ***[date] de *[PHP] da formato a la hora actual: [H] para las horas, [i] para los minutos y [s]** para los segundos;
    • Línea 21: la función [view] hace que [Blade] genere la página. El primer parámetro es el nombre de la vista: la ruta del archivo, relativa a la carpeta [resources/views], donde las [/]s se reemplazan por puntos, y sin la extensión [.blade.php]: [views.index] remite al archivo [resources/views/views/index.blade.php]. El segundo parámetro es un arreglo asociativo, en el que cada clave se convierte en una variable de la vista; en este caso, una sola: [$model]. [view] devuelve un objeto [View], que [Laravel] transforma en una respuesta (de tipo [text/html]) al generar la página;
    • Línea 29: otra vista, con una variable distinta ([$name]). [response()->view(...)] genera una respuesta a partir de una vista, con el código especificado (en este caso, 404) para mostrar una página de error personalizada. El tipo de la acción [View|Response] significa: o bien una [View] o bien una [Response];
    • líneas 31–35: la misma vista que la acción [index], pero con una plantilla distinta. Este es el beneficio de separar las acciones de las vistas: una misma vista puede ser utilizada por varias acciones.

    • Líneas 9–12: las directivas [@php] y [@endphp] delimitan un bloque de código [PHP], que se ejecuta en este punto de la página. Allí se crean dos variables de la vista: el precio total, calculado por el método [sum] de una colección (ejemplo 03), que suma una propiedad de cada elemento, y el número de productos. El bloque [@php] debe reservarse para este tipo de preparación: el cálculo normalmente corresponde a la acción;
    • línea 17: un valor [null] se muestra como una cadena vacía. El operador [??] de [PHP] (ejemplo 08) reemplaza un valor [null] por un valor predeterminado;
    • Líneas 19–20: [{{ }}] escapa el HTML (2a); [{!! !!}], en cambio, inserta el valor tal cual, sin escaparlo (2b). [{!! !!}] se reserva para el HTML generado por la propia aplicación, nunca para lo que ingresa el usuario;
    • líneas 22–26: una condición: [@if], [@elseif], [@else], [@endif], con una condición [PHP] entre paréntesis. Cada bloque se cierra con una directiva [@end...];
    • líneas 30–36: un bucle [@foreach] ... [@endforeach], que se escribe como el bucle [foreach] de [PHP]. Dentro de él, la variable especial [$loop] describe el estado del bucle: [$loop->index] (el número de iteración, que comienza en 0), [$loop->iteration] (que comienza en 1), [$loop->first], [$loop->last] (verdadero en la primera y en la última iteración), [$loop->count] (el número de elementos). Las variables externas al bucle ([$model->name]) siguen siendo accesibles;
    • Línea 32: el operador ternario de [PHP], [condition ? a : b] (ejemplo 11);
    • línea 40: la directiva [@forelse] ... [@empty] ... [@endforelse] es un bucle en el que el bloque [@empty] se ejecuta si la lista está vacía. Es más simple que un [@if] que probara la longitud de la lista;
    • líneas 43–44: expresiones calculadas ([$total / $count]) y las variables del bloque [@php]. La función [number_format] de [PHP] da formato a un número: dos decimales, un punto como separador decimal y una coma como separador de miles. En el ejemplo 16 veremos una manera mucho mejor de dar formato a números e importes;
    • Línea 46: el operador [->] recorre los objetos ([$model->address->city]), y se puede llamar a cualquier función de [PHP]: [mb_strtoupper] pasa una cadena a mayúsculas (las funciones [mb_...], de *multi-byte*, manejan correctamente los caracteres acentuados codificados en UTF-8);
    • línea 48: el carácter [@] solo es interpretado por [Blade] al comienzo de una palabra; en una dirección de correo electrónico, se copia tal cual. Para escribir un [@] seguido del nombre de una directiva, se duplica: [@@if] produce [@if]. De igual manera, [@{{ ... }}] produce [{{ ... }}], lo que resulta útil cuando una página contiene llaves destinadas a un framework [JavaScript].

    Una nota sobre los comentarios: [Blade] procesa [@php] los bloques antes que los comentarios. Un comentario que contuviera la palabra [@php] sería interpretado, por lo tanto, como el inicio de un bloque de código, con resultados inesperados: por eso el comentario de la línea 8 no la incluye.

// los ejemplos 15 a 28 (la carpeta examples/common/bootstrap), bajo la URL /bootstrap/...

use Illuminate\Support\Facades\Route;

Route::get('bootstrap/{file}', function (string $file) {
    $folder = realpath(__DIR__.'/bootstrap');
    // realpath: la ruta absoluta del archivo solicitado, sin el . ni el .. ; false
    // si el archivo no existe
    $path = realpath($folder.'/'.$file);
    // un archivo que existe, y que está efectivamente DENTRO de la carpeta (sin ../ para salir de ella)
    abort_unless($path && str_starts_with($path, $folder.DIRECTORY_SEPARATOR)
        && is_file($path), 404);
    // el tipo del archivo, a partir de su extensión
    $types = ['css' => 'text/css', 'js' => 'text/javascript', 'map' => 'application/json'];
    $type = $types[pathinfo($path, PATHINFO_EXTENSION)] ?? 'application/octet-stream';
    return response()->file($path, ['Content-Type' => $type]);

    • líneas 8–14: servir archivos designados por una URL exige una precaución: una URL como [/bootstrap/../../15-layout/.env] no debe dar acceso a un archivo situado fuera de la carpeta. Se verifica que la ruta resultante comience efectivamente con la ruta de la carpeta ([str_starts_with]) y que designe un archivo ([is_file]); de lo contrario, [abort_unless] termina la solicitud con un error 404. namespace App\Helpers;

use Brick\Math\BigDecimal;

class Formats

    // "keyboard" -> "KEYBOARD"
    public static function uppercase(?string $text): string
    {

    }

    // un monto en una moneda, en el formato del idioma de la solicitud (véase el
    // middleware SetLanguage): 1149.9 -> "€1,149.90" en inglés, "1 149,90 €" en
    // francés. La extensión intl de PHP conoce las convenciones de cada país
    public static function money(BigDecimal $amount, string $currency = 'EUR'): string
    {

    }

    // una fecha con palabras completas, en el idioma de la solicitud: "Saturday 26 September 2026"
    public static function longDate(CarbonInterface $day): string
    {

    private const GENRES = ['novel', 'poetry', 'drama'];

    /** @return list<Book> */
    private static function books(): array
    {
        return [
            new Book('Le Rouge et le Noir', 'Stendhal', 'novel'),
            new Book('Les Fleurs du mal', 'Baudelaire', 'poetry'),
            new Book('Madame Bovary', 'Flaubert', 'novel'),

    public function search(Request $request): View
    {
        // string: el parámetro, en forma de cadena ('' si falta)
        $keyword = $request->string('keyword')->value();

        $word = mb_strtolower($keyword);
        $results = array_values(array_filter(self::books(), fn (Book $book) =>
            ($word === '' || str_contains(mb_strtolower($book->title), $word)
                || str_contains(mb_strtolower($book->author), $word))
            && ($genre === '' || $book->genre === $genre)));

            'model' => new SearchModel($keyword, $genre, self::GENRES, $results),
        ]);

    4.8. Ejemplo 20: el patrón Post/Redirect/Get

    Cuando una acción POST devuelve una página, esa página es el resultado de un POST. Si el usuario actualiza la página (presionando [F5]), el navegador vuelve a enviar la solicitud POST, tras una advertencia que pocas personas leen: el comando se envía dos veces y el mensaje se publica dos veces. El patrón Post/Redirect/Get (PRG) evita este problema: una acción POST exitosa no devuelve una página; responde con una redirección (ejemplo 04) a una página GET, que el navegador solicita de inmediato. Recargar esta página simplemente vuelve a ejecutar la acción GET.

    Queda un problema: la página GET querría mostrar un mensaje (“la tarea ha sido agregada”), pero es la acción POST la que conoce este mensaje, y no puede pasar una variable a una solicitud que aún no ha ocurrido. La solución: el mensaje flash, almacenado en la sesión por la acción POST, se conserva hasta la siguiente solicitud, se muestra y luego se descarta. Este es el mecanismo que [Laravel] ya utilizaba, en el ejemplo 19, para los errores de formulario.

// app/Services/TasksService.php: la lista de tareas, compartida por todos los

namespace App\Services;

use Illuminate\Support\Facades\Cache;

class TasksService
{
    private const KEY = 'tasks';

    /** @return list<string> */
    public function list(): array
    {
        // el valor almacenado bajo la clave [tasks], o la lista inicial
        return Cache::get(self::KEY, ['Read chapter 3']);
    }

    public function add(string $label): void
    {
        // varias solicitudes pueden ejecutarse AL MISMO TIEMPO (el servidor las atiende
        // en varios procesos): un bloqueo garantiza que solo una a la
        // vez lea, modifique y reescriba la lista. block(5, ...) espera el bloqueo 5
        // segundos como máximo, ejecuta la función y luego libera el bloqueo
        Cache::lock('tasks-lock', 10)->block(5, function () use ($label) {
            $tasks = $this->list();
            $tasks[] = $label;
            // forever: el valor se conserva sin límite de tiempo
            Cache::forever(self::KEY, $tasks);
        });
    }
}

    La lista de tareas es compartida por todos los usuarios y debe persistir de una solicitud a la siguiente. En [Java], [C#] o [Python], se mantendría en memoria dentro de un único servicio. En [PHP], esto es imposible: como vimos en los ejemplos 01 y 06, nada sobrevive a la solicitud. Por lo tanto, la lista debe almacenarse fuera de [PHP]: en una base de datos, en un archivo... o en la caché de [Laravel], que es la que utilizamos aquí.

    • Línea 18: la interfaz [Cache] proporciona acceso a la caché de la aplicación: un almacén de pares clave→valor. El archivo [.env] de los ejemplos almacena estos datos en archivos dentro de la carpeta [storage/framework/cache] ([CACHE_STORE=file], ejemplo 01); en producción, se prefiere un servidor dedicado, como [Redis]. [get] devuelve el valor almacenado bajo una clave, o el valor predeterminado proporcionado como segundo parámetro. Se puede almacenar cualquier valor (en este caso, un arreglo de cadenas): [Laravel] lo serializa, es decir, lo convierte en texto, mediante la función [serialize] de [PHP];

    4.9. Ejemplo 21: enlaces, botones y confirmación

    Un principio del protocolo HTTP: una solicitud GET no cambia nada. Los navegadores, los motores de búsqueda y las herramientas que precargan páginas siguen los enlaces libremente, sin pedir permiso al usuario.     • la consulta se realiza mediante un enlace ([<a href>]), que envía una solicitud GET;
    • la modificación (guardar, duplicar, eliminar) se realiza mediante un botón colocado en un formulario, protegido por un token anti-CSRF.

// app/Services/ContactsService.php: los contactos, compartidos por todos, almacenados en
// la caché de Laravel (véase el ejemplo 20)

namespace App\Services;

use App\Models\Contact;
use Illuminate\Support\Facades\Cache;

class ContactsService
{
    private const KEY = 'contacts';

    /** @return array{contacts: list<Contact>, lastId: int} */
    private function data(): array
    {
        return Cache::get(self::KEY, [
            'contacts' => [
                new Contact(1, 'Marie Durand', '01 23 45 67 89'),
                new Contact(2, 'Paul Martin', '06 12 34 56 78'),
                new Contact(3, 'Philippe Jandot', '02 98 76 54 32'),
            ],
            'lastId' => 3,
        ]);
    }

    // una modificación de los datos, bajo bloqueo: la función recibe los datos,
    // los modifica (&) y devuelve el resultado de la operación
    private function editData(callable $operation): mixed
    {
        return Cache::lock('contacts-lock', 10)->block(5, function () use ($operation) {
            $data = $this->data();
            $result = $operation($data);
            Cache::forever(self::KEY, $data);
            return $result;
        });
    }

    /** @return list<Contact> */
    public function list(): array
    {
        return $this->data()['contacts'];
    }

    // el contacto, o null si no existe
    public function read(int $id): ?Contact
    {
        return array_find($this->list(), fn (Contact $c) => $c->id === $id);
    }

    public function edit(int $id, string $name, string $phone): ?Contact
    {
        return $this->editData(function (array &$data) use ($id, $name, $phone) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // un contacto es inmutable (readonly): construimos uno nuevo,
                    // que reemplaza al anterior en el arreglo
                    return $data['contacts'][$i] = new Contact($id, $name, $phone);
                }
            }
            return null;
        });
    }

    public function add(string $name, string $phone): Contact
    {
        return $this->editData(function (array &$data) use ($name, $phone) {
            $contact = new Contact(++$data['lastId'], $name, $phone);
            $data['contacts'][] = $contact;
            return $contact;
        });
    }

    public function delete(int $id): ?Contact
    {
        return $this->editData(function (array &$data) use ($id) {
            foreach ($data['contacts'] as $i => $contact) {
                if ($contact->id === $id) {
                    // array_splice elimina el elemento i del arreglo y renumera los siguientes
                    array_splice($data['contacts'], $i, 1);
                    return $contact;
                }
            }
            return null;
        });
    }
}

    Los contactos se almacenan en la caché, igual que las tareas del ejemplo 20. Cada contacto es un objeto [Contact] inmutable (un ID, un nombre, un número de teléfono), almacenado en un arreglo junto con el último ID asignado. Algunos puntos sobre [PHP]:

    • Líneas 29–37: todas las modificaciones siguen el mismo patrón: adquirir el bloqueo, leer los datos, modificarlos, escribirlos de nuevo y liberar el bloqueo. Este método escribe en el arreglo una sola vez; cada modificación le pasa una función (de tipo [callable], “invocable”) que recibe los datos y los modifica. La función debe modificar el propio arreglo, no una copia: su parámetro se declara como [array &$data], donde [&] especifica un paso por referencia (sin [&], un arreglo se copia; véase el ejemplo 06);
    • líneas 51–63: un contacto es inmutable: se crea uno nuevo, que reemplaza al anterior en el arreglo. Una asignación es una expresión cuyo valor es el valor asignado: [return $data['contacts'][$i] = new Contact(...)] reemplaza el contacto y lo devuelve;
    • línea 68: [++] colocado antes de una variable la incrementa en 1 y devuelve el nuevo valor;
    • línea 80: [array_splice] elimina un elemento del arreglo y vuelve a numerar los elementos siguientes;
    • Los métodos devuelven [null] para un contacto inexistente: le corresponde al controlador decidir la respuesta.

// app/Http/Controllers/ContactsController.php: enlaces (GET) y botones (POST, DELETE)

namespace App\Http\Controllers;

use App\Models\Contact;
use App\Services\ContactsService;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\View\View;

class ContactsController
{
    public function __construct(private ContactsService $contacts)
    {
    }

    // el contacto, o una respuesta 404 si no existe
    private static function contactOr404(?Contact $contact): Contact
    {
        abort_if($contact === null, 404, 'unknown contact');
        return $contact;
    }

    // un ENLACE (<a href>): una solicitud GET, que no modifica nada
    public function list(): View
    {
        return view('contacts.list', ['contacts' => $this->contacts->list()]);
    }

    public function details(int $id): View
    {
        return view('contacts.details', ['contact' => self::contactOr404($this->contacts->read($id))]);
    }

    // un BOTÓN en un formulario POST: una solicitud que modifica datos
    public function save(Request $request, int $id): RedirectResponse
    {
        $contact = self::contactOr404($this->contacts->edit($id,
            $request->string('name')->value(), $request->string('phone')->value()));
        return redirect()->route('contacts')->with('message', "The contact [$contact->name] has been edited.");
    }

    // el mismo formulario, otro botón (atributo formaction): otra acción
    public function duplicate(Request $request, int $id): RedirectResponse
    {
        $copy = $this->contacts->add($request->string('name')->value().' (copy)',
            $request->string('phone')->value());
        return redirect()->route('contacts')->with('message', "The contact [$copy->name] has been created.");
    }

    // una solicitud DELETE, simulada por un formulario POST (véase @method en la vista)
    public function delete(int $id): RedirectResponse
    {
        $contact = self::contactOr404($this->contacts->delete($id));
        return redirect()->route('contacts')->with('message', "The contact [$contact->name] has been deleted.");
    }
}

// Sin JavaScript, estos formularios simplemente se envían sin confirmación.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // el formulario que se enviará si el usuario confirma

  // 1. interceptamos el envío de los formularios por confirmar
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // el envío se suspende
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // aparece la ventana
    });
  });

  // 2. los dos botones de la ventana
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // envío, SIN volver a disparar el evento 'submit'
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • línea 3: el código está encerrado en una función anónima, que se ejecuta de inmediato; sus variables no interfieren con las de los demás scripts de la página;
    • líneas 4–6: la ventana, la ubicación del mensaje y el formulario en espera de confirmación;
    • líneas 9–14: para cada formulario que tiene un atributo [data-confirmation], se intercepta el evento [submit], que se desencadena cuando se envía el formulario. [preventDefault()] suspende el envío; el formulario se pone en espera y su mensaje ([dataset.confirmation], el valor del atributo [data-confirmation]) se muestra en la ventana, que aparece;
    • líneas 19–25: un único manejador para los clics en la ventana: [event.target] es el elemento en el que se hizo clic; su atributo [data-action] especifica de qué botón se trata. “Yes” envía el formulario pendiente mediante el método [submit()], que, a diferencia de hacer clic en un botón, no desencadena el evento [submit] (de lo contrario, la ventana volvería a aparecer); “No” oculta la ventana.

    Sin [JavaScript], el formulario simplemente se envía sin confirmación: la página sigue siendo utilizable. Esto es mejora progresiva: [JavaScript] agrega comodidad, pero la aplicación no depende de él.
