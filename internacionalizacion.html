    5. Internacionalización

    Una aplicación internacionalizada muestra su texto en el idioma del usuario. El caso de estudio está en francés e inglés. El principio es simple: las vistas ya no contienen texto, sino claves ([MENU.HOME]), y un diccionario para cada idioma asocia un texto a cada clave. El idioma seleccionado se almacena en una cookie.

    [Laravel] tiene su propio sistema de traducción, que ya vimos en el ejemplo 09 para los mensajes de validación. Acepta dos tipos de diccionarios, almacenados en la carpeta [lang]: archivos [PHP], uno por tema y por idioma ([lang/fr/validation.php]), que devuelven un arreglo de claves; y archivos JSON, uno por idioma ([lang/fr.json]), donde cada clave es una cadena arbitraria. Utilizamos el segundo formato: salvo por la sintaxis de los parámetros, son los mismos diccionarios que los de las versiones [ASP.NET Core MVC], [NestJS], [Spring MVC] y [Flask] del caso de estudio, y su formato se puede leer y escribir sin herramientas especiales. El formato de fechas e importes sigue siendo el mismo que en el ejemplo 16.

    Un diccionario JSON es un objeto en el que cada par asocia una clave con su texto. Las claves se agrupan por tema según su prefijo: el texto de menú “Accueil” tiene la clave [MENU.HOME]. Un texto puede contener marcadores de posición, escritos como [:name], que se reemplazan durante la traducción. (Los diccionarios de las otras versiones del caso de estudio anidan los objetos JSON — [{"MENU": {"HOME": "Accueil"}}] — y escriben los parámetros como [{name}]; los de [Laravel] son “planos” y utilizan la sintaxis [:name].) El archivo [lang/en.json] tiene exactamente las mismas claves:

    Si falta una clave en el diccionario JSON del idioma actual, se busca en los archivos [PHP] de la carpeta de ese idioma ([lang/fr/*.php], ejemplo 09) y luego en los del idioma de respaldo ([APP_FALLBACK_LOCALE], inglés de forma predeterminada). No existe un diccionario de respaldo (JSON): una clave ausente del diccionario (JSON) del idioma actual y de estos archivos se muestra tal cual. De este modo, cualquier omisión resulta visible de inmediato en pantalla.

    <?php
// app/Http/Middleware/SetLanguage.php: el idioma de cada solicitud

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\App;
use Symfony\Component\HttpFoundation\Response;

class SetLanguage
{
    // los idiomas admitidos; el primero es el idioma predeterminado
    public const LANGUAGES = ['en', 'fr'];

    public const COOKIE = 'language';

    // el idioma de la cookie [language] si es admitido, inglés en caso contrario
    public function handle(Request $request, Closure $next): Response
    {
        $language = $request->cookie(self::COOKIE);
        App::setLocale(in_array($language, self::LANGUAGES, true) ? $language : self::LANGUAGES[0]);
        return $next($request);
    }
}
    • líneas 14–16: los idiomas admitidos y el nombre de la cookie: constantes de clase públicas, accesibles desde otras clases ([SetLanguage::LANGUAGES]);
    • líneas 21–22: antes de cada acción, el idioma de la solicitud: el idioma especificado en la cookie [language] si existe y es admitido; de lo contrario, inglés. [$request->cookie(name)] devuelve el valor de una cookie enviada por el navegador, o [null]. [in_array], con [true] como tercer parámetro, compara también los tipos ([===]). [App::setLocale] (ejemplo 16) establece el idioma de la aplicación para la solicitud: es el idioma utilizado para las traducciones y el formato.

    ->withMiddleware(function (Middleware $middleware): void {

        // el servidor acepta solo los idiomas admitidos
        $middleware->encryptCookies(except: [SetLanguage::COOKIE]);

        $middleware->web(append: SetLanguage::class);
    })
    ->withExceptions()
    ->booted(function () {
        // en las vistas: @money($price) (véase el ejemplo 16)
        Blade::directive('money', fn (string $expression) =>
            "<?php echo e(\\App\\Helpers\\Formats::money($expression)); ?>");
    })
    ->create();

La cookie [language] no contiene información secreta, y el servidor solo acepta los idiomas admitidos: la excluimos del cifrado, lo que nos permite verla (y crearla) con [curl]. El ejemplo siguiente volverá sobre este cifrado;

    • líneas 26–27: la directiva [@money] del ejemplo 16.

    <?php
// app/Helpers/Formats.php: fechas y montos, formateados en el idioma de la solicitud (véase el ejemplo 16)

namespace App\Helpers;

use Brick\Math\BigDecimal;
use Carbon\CarbonInterface;
use Illuminate\Support\Facades\App;
use Illuminate\Support\Number;

class Formats
{
    // un monto en euros
    public static function money(BigDecimal $amount): string
    {
        return Number::currency($amount->toFloat(), in: 'EUR', locale: App::getLocale());
    }

    // una fecha con palabras completas. El formato "dddd LL": el día de la semana y luego la
    // fecha en el formato "largo" del idioma: "mercredi 23 septembre 2026" en francés,
    // "Wednesday September 23, 2026" en inglés
    public static function longDate(CarbonInterface $day): string
    {
        return $day->locale(App::getLocale())->isoFormat('dddd LL');
    }
}
    • Línea 24: [LL] es un formato localizado: cada idioma tiene el suyo ([23 septembre 2026] en francés, [September 23, 2026] en inglés), mientras que [D MMMM YYYY] impondría el orden francés a todos los idiomas. [dddd] agrega el día de la semana.

    <?php
// app/Http/Controllers/LanguageController.php: la elección del idioma

namespace App\Http\Controllers;

use App\Http\Middleware\SetLanguage;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;

class LanguageController
{
    // GET /language/fr: almacena la elección en una cookie y luego regresa a la página anterior
    public function change(Request $request, string $code): RedirectResponse
    {
        abort_unless(in_array($code, SetLanguage::LANGUAGES, true), 404);
        // la cookie: un año de vida (en minutos), ilegible para el JavaScript de la
        // página (httpOnly), nunca enviada con una solicitud POST proveniente de otro sitio (sameSite)
        return redirect(self::originPage($request))
            ->withCookie(cookie(SetLanguage::COOKIE, $code, 365 * 24 * 60, httpOnly: true, sameSite: 'lax'));
    }

    // la página de la que venimos (encabezado Referer), de la cual conservamos solo la ruta:
    // redirigir a una dirección completa proveniente de la solicitud permitiría
    // enviar al usuario a otro sitio (falla de "redirección abierta", open redirect)
    private static function originPage(Request $request): string
    {
        // parse_url divide una URL en sus componentes (ruta, parámetros...)
        $url = parse_url($request->header('Referer', ''));
        $path = $url['path'] ?? '';
        // "//site.com/..." sería entendida por el navegador como una dirección
        // de OTRO sitio: también se rechaza
        if (! str_starts_with($path, '/') || str_starts_with($path, '//')) {
            return '/';
        }
        return isset($url['query']) ? "$path?{$url['query']}" : $path;
    }
}
    • línea 15: un código de idioma desconocido: 404;
    • líneas 18–19: la acción responde con una redirección a la página de la que venía el usuario; este vuelve a esa página en el nuevo idioma. La respuesta incluye una cookie, que el navegador enviará de vuelta con cada solicitud: la función [cookie] la crea y el método [withCookie] la agrega a la respuesta. Sus parámetros: el nombre, el valor, la duración en minutos (un año) y dos parámetros con nombre: [httpOnly: true] la hace invisible para el [JavaScript] de la página; [sameSite: 'lax'] impide que el navegador la envíe con una solicitud POST originada en otro sitio;
    • líneas 25–36: la página de origen la especifica el encabezado [Referer] de la solicitud (la grafía incorrecta, con una sola [r], es la que se usa en el estándar HTTP), que el navegador rellena con la URL de la página que contenía el enlace. Pero este encabezado proviene del cliente, que puede poner en él lo que quiera. Redirigir a ciegas a esta dirección convertiría nuestra aplicación en una *open redirect*: un enlace malicioso con el nombre de nuestro dominio podría enviar al usuario a un sitio malicioso. Por lo tanto, conservamos solo la ruta y los parámetros de la URL (la función [parse_url] de [PHP] la descompone en sus componentes, almacenándolos en un arreglo asociativo), y rechazamos cualquier ruta que comience con [//], que el navegador interpretaría como la dirección de otro sitio. [Laravel] también ofrece [redirect()->back()] (o [back()]), que redirige a la página anterior almacenada en la sesión (ejemplo 20), y no al encabezado [Referer]: lo utilizaremos en el caso de estudio.
